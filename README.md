# Тихая гавань

Минималистичный морской бой для браузера, созданный для второго этапа Narxoz Incubator 2026. Игра против компьютера, с другом по ссылке и со случайным соперником. Русский, казахский и английский интерфейсы; регистрация не требуется.

## Возможности

- Полная партия до победы, поражения или сдачи.
- Три сложности компьютера без доступа к скрытому флоту.
- Гостевые комнаты, приглашения и случайный подбор реальных игроков.
- Ручная расстановка нажатиями и автоматическая генерация.
- Сохранение схемы флота для следующей игры.
- 60 секунд на выстрел; попадание запускает новый срок, просрочка передаёт очередь.
- Пауза при потере связи и 60 секунд на возвращение.
- Восстановление партии после обновления в том же браузере.
- Победы и поражения отдельно против компьютера и людей.
- Раскрытие полей после результата и взаимный реванш.
- Адаптивный интерфейс без звука, подписи клеток и видимый фокус клавиатуры.

## Правила и управление

Поле 10 × 10, координаты A–J и 1–10. Флот: один четырёхпалубный, два трёхпалубных, три двухпалубных и четыре однопалубных корабля. Корабли прямые, не пересекаются и не касаются даже по диагонали.

На расстановке можно оставить предложенный флот, нажать «Случайно» или «Очистить» и выставить корабли вручную. Выберите длину, ориентацию кнопкой «Повернуть» и начальную клетку. Нажатие на поставленный корабль убирает его. «Готов к бою» доступно для полного допустимого флота. После готовности размещение заблокировано.

Первый игрок выбирается случайно. Попадание сохраняет очередь и даёт новые 60 секунд. Промах или просрочка передаёт ход. Повторный выстрел запрещён. Клетки вокруг потопленного корабля автоматически исключаются из целей. Побеждает первый уничтоживший весь флот соперника.

Крестик означает попадание, точка — промах или исключённую клетку. Тёмный цвет показывает потопленный корабль. «Сдаться» фиксирует поражение после подтверждения. Выход из комнаты до начала отменяет подготовку без поражения. Реванш требует согласия обоих.

Для друга создайте комнату и отправьте ссылку. Для случайного подбора нужны два реальных гостя; при отсутствии второго человека приложение ожидает, не подменяя его ботом. Для проверки на одном компьютере используйте разные браузеры или независимый приватный профиль. Две обычные вкладки одного браузера представляют одного гостя.

## Технологии и структура

TypeScript, React 19, Vinext, Vite, Cloudflare Workers, Cloudflare D1 и Drizzle. Иконки Lucide, шрифт Manrope из Google Fonts с системным резервным шрифтом. LocalStorage используется для явно локальных данных: партии с ботом, её результатов, схемы флота и языка.

- `lib/game.ts` — правила, валидатор, расстановка и стратегии бота.
- `lib/arena.ts` — комнаты, подбор, таймеры и фильтрация видимого состояния.
- `app/api/game/route.ts` — гостевые сессии, D1 и проверка конкурентных изменений.
- `app/page.tsx`, `app/globals.css` — интерфейс.
- `lib/i18n.ts` — три языковых словаря.
- `db/schema.ts`, `drizzle/` — схема и миграции.
- `tests/run.mjs` — проверки правил и модели матчей.
- `tests/api.mjs` — интеграционные проверки HTTP API.

## Честность и сохранение

Сервер определяет исход каждого сетевого выстрела. Клиент передаёт клетку, версию партии и идентификатор команды. Сервер проверяет участника, очередь, срок и допустимость цели. Повтор команды не создаёт второй выстрел. Изменение общей арены выполняется условным обновлением по версии; при конфликте состояние читается заново.

Скрытый флот не передаётся сопернику до завершения матча. Гостевой доступ подтверждается случайным 256-битным токеном в HttpOnly-cookie; сервер использует SHA-256 токена. В HTTPS cookie получает Secure. Ссылка комнаты не позволяет действовать от имени создателя.

Лёгкий бот выбирает случайные клетки. Средний добивает корабли после попадания. Сложный оценивает допустимые позиции оставшегося флота по известным выстрелам. Функция выбора цели принимает наблюдения, а не флот игрока. Полное состояние локальной игры находится в браузере; этот режим не является защищённым рейтингом.

Клиенты обновляют сетевое состояние каждые три секунды. После 12 секунд без активности определяется потеря связи, затем даются 60 секунд на возвращение. Во время ожидания сохраняется остаток времени хода; переподключение не даёт новый полный ход.

Дедлайны основаны на серверном времени. Их последствия применяются при очередном запросе, в том числе от второго игрока. Если запросов нет вообще, запись не меняется в фоне, но при возвращении результат рассчитывается по сохранённым срокам. Отдельного фонового планировщика нет.

Если один игрок не вернулся, а второй остаётся на связи, первый проигрывает. Если отсутствуют оба, победителя нет. Общая недоступность сервиса может выглядеть как отключение обоих и не даёт автоматической победы одной стороне.

Результат записывается по уникальному идентификатору матча, что исключает двойной подсчёт. Полные завершённые комнаты очищаются через час при очередном обращении; числовые результаты сохраняются. Неактивная подготовка очищается через десять минут.

Очистка cookie удаляет доступ к прежнему гостю. Перенос на другое устройство, восстановление по почте и отдельная история партий не предусмотрены.

## Локальный запуск

Требуются Node.js 22.13 или новее и npm. Используйте закреплённые зависимости из lockfile.

```sh
npm ci
npm run build
```

На новой локальной базе выполните миграции **один раз**, по порядку:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_bitter_puma.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_useful_hammerhead.sql
npm run dev
```

Откройте адрес, напечатанный сервером, обычно `http://127.0.0.1:5173/`. В следующие разы достаточно `npm run dev`. Не запускайте уже применённые SQL-файлы повторно. Локальные данные находятся в игнорируемой папке `.wrangler/state`.

`npm start` запускает собранную версию локально. Для сетевой игры нужен Worker-совместимый сервер с D1-привязкой `DB`; статический GitHub Pages для неё не подходит. Текущим размещением управляет Sites; логические настройки — в `.openai/hosting.json`. Реальные ключи и секреты не помещаются в репозиторий.

## Проверки

```sh
npm test
npm run typecheck
```

При запущенном локальном сервере и применённой схеме:

```sh
npm run test:api
```

API-тест создаёт тестовых гостей, комнаты и результаты в локальной базе. Не направляйте его на рабочую базу пользователей. Перед ним `npm test` готовит временные JavaScript-модули в `.sites-runtime/tests`.

Проверки включают 250 случайных флотов и 30 полных партий ботов, границы, касания, повторные выстрелы, победу, сдачу, таймеры, восстановление, скрытие поля, подбор и реванш. API-тест проводит полную сетевую партию, проверяет повтор команды, однократный результат и одновременный подбор четырёх гостей.

## Ограничения

- Прототип для небольшой аудитории: до 100 активных комнат. Общая арена с контролем версии обеспечивает согласованность, но не рассчитана на массовую нагрузку.
- Синхронизация опросом даёт задержку до нескольких секунд. WebSocket не используется.
- Реальных платежей, подписок, тренера, рейтингов, турниров и дополнительных режимов нет.
- Доступность размещения зависит от Sites и действующих лимитов платформы. Платные внешние сервисы и автоматические списания в приложении не подключены.
- Случайный подбор требует другого ожидающего пользователя.
- Проверка при ширине 393 пикселя не заменяет физическую проверку iPhone 15 в Chrome и Яндекс Браузере. Её необходимо выполнить перед сдачей.
- Локальные результаты можно изменить средствами браузера; они не используются для рейтинга.
- Казахский перевод желательно дополнительно вычитать носителю языка.
